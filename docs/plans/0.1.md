# Plan for 0.1: read text from an image on Android

> Started on 22/10/2026. Status: **milestone 1 next**.

## Goal

An app gives the plugin an image file and gets back the printed text in it, with positions, read on the device by ML Kit. Android only (D4); everywhere else, a clear "unsupported" error.

**Done when:** in the example app on a real Android phone, a photo of the back of a book shows its text with boxes over the image, the ISBN line included, with the phone in airplane mode once the model is on the device.

## The API

A proposal, to settle in milestone 1.

```ts
import { recognizeText } from 'tauri-plugin-text-recognition-api'

const result = await recognizeText({ path })   // a file path or a content:// URI

interface RecognizedText {
  text: string            // all the text, blocks separated by a blank line
  imageWidth: number      // the image as ML Kit saw it, after its rotation is applied
  imageHeight: number
  blocks: TextBlock[]
}

interface TextBlock {
  text: string
  box: Box
  lines: TextLine[]
}

interface TextLine {
  text: string
  box: Box
  confidence: number | null   // 0 to 1, when the engine gives it
  angle: number | null        // degrees, when the engine gives it
}

interface Box { left: number; top: number; width: number; height: number }   // pixels
```

- No text in the image: an empty `blocks` and an empty `text`, not an error.
- An image that cannot be opened or decoded, or a model that is not available yet: an error with a message that says which.
- Words (ML Kit's "elements") are left out of 0.1: lines are enough for both uses we know of. They can be added later without breaking anything.

## Milestones

1. **The skeleton becomes the plugin.** Replace the generated `ping` with `recognize_text` on the three sides (Rust models and command, Kotlin `@Command` that answers with an empty result, TypeScript function), the permission, desktop returning `Unsupported`. Rust tests for the JSON shape of the models (field names in `camelCase`). CI: format, Clippy and tests on Linux only, with the actions pinned to a commit SHA; the scheduled audit replaced by `cargo deny` or kept, to decide.
2. **ML Kit on Android.** `InputImage.fromFilePath` (handles `file://` and `content://`), the Latin recognizer, the mapping from ML Kit's `Text` to the result, and the errors. Check the current version of the dependency and confirm D5.
3. **The example app.** Pick an image (Tauri's dialog plugin), call the plugin, draw the boxes over the image and list the lines. The maintainer tries it on a phone: a book's back cover, a shelf of spines, a blurry photo, an image with no text, airplane mode.
4. **Documentation for 0.1.** README with the real API and a complete example, `docs/README.md` updated, the changelog.
5. **Publish 0.1.0.** crates.io and npm (accounts and tokens are the maintainer's), a GitHub release, and a line in the community plugin lists. Then Kosmotheka can use it (its own plan).

## Open questions

- **D5:** the model in Play Services or inside the app. Proposal: Play Services.
- **Live camera** (D6): after 0.1, once Kosmotheka has tried reading the ISBN from a photo. If a photo is clumsy, live reading comes next.
- **Other scripts** (Chinese, Devanagari, Japanese, Korean): ML Kit has them as separate dependencies. Not in 0.1; perhaps as Gradle options later.
- **npm name:** unscoped `tauri-plugin-text-recognition-api`, or scoped `@kosmotheka/…`. Check that the names are free before publishing.
